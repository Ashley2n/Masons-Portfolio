# Gotchas

Things that cost time once. Moved out of `docs/handoff.md` on 2026-11-14 so the handoff stays short; this file is still active, so add new gotchas here, not in the handoff. `docs/handoff.md` links here.

- **Start `npm run dev` from the `D:` path, never through the junction.** `C:\Users\aa\Documents\01-Projects` is a junction to `D:\01-Projects`. Started from `C:\Users\aa\Documents\01-Projects\...\Masons-Portfolio`, Next 16.4.3's dev server answered every request with a 500 and `ENOENT ... C:\...\D:\...\D:\...\.next\dev\routes-manifest.json` (a `D:` path joined onto the `C:` working directory, possibly at `node_modules/next/dist/server/lib/router-utils/setup-dev-bundler.js:157`; not confirmed as the cause). Started from `D:\01-Projects\Client-Projects\Masons-Portfolio` it works (Ashley, 2026-11-08). Open the terminal and editor at the `D:` path. No wrapper script was built; ⚠ unsourced whether it was always like this.
- **Playwright MCP screenshots of Motion animations:** the MCP browser does not tick `requestAnimationFrame` while it idles in `browser_wait_for`, so a screenshot after a plain wait shows a stale, half-faded frame even 8s after load (checked 2026-11-08: the page ran at 61 fps once evaluated, and the h1 was at full opacity). Keep frames running first with `browser_evaluate` (a `requestAnimationFrame` loop for the time you want), then take the screenshot. The e2e tests are not affected (real Chrome).
- **Hydration warning with reduced motion (fixed 2026-11-15, dev-only):** Motion 14.10.1's `useReducedMotion` is `useState(prefersReducedMotion.current)`, so it reads the real setting on the *first client render*, not after hydration (the old comments in `Reveal.tsx` and `CountUp.tsx` said otherwise). The server always sends the hidden start state, so with `reducedMotion: "reduce"` React warned "A tree hydrated but some attributes ... didn't match" (`opacity: "0.5"` vs `1`). Measured on the production build: 0 console messages and no stale inline styles on `/`, `/about`, `/media`, so visitors never saw it; it was the dev overlay's "1 Issue". Fix: `suppressHydrationWarning` on `LoadItem` and `Reveal` (React skips the attribute comparison, `node_modules/react-dom/cjs/react-dom-client.development.js:21479`), pinned by `components/motion/hydration.test.tsx` (production e2e cannot see a dev-only warning). The unrelated dev line "You have Reduced Motion enabled on your device" is Motion's own notice and stays.
- **Playwright `click()` re-scrolls on the phone project:** the button's box wobbles by about 0.1px after `scrollIntoViewIfNeeded` (Pixel 7, 2.625 DPR), Playwright reports "element is not stable", retries the click with another scroll alignment and the page moves about 410px (half the viewport). A `click({ trial: true })` first does not fix it (traced 2026-11-15: the retry can still land after it; a trial click also sends a swallowed click event to `window`). If a test compares scrollY around a click, record `window.scrollY` inside the page from a capture-phase `click` listener, not from the test before the click (`e2e/media.spec.ts`, "Load more" test: 3 of 30 failed before, 0 of 120 after).
- **Timing tests can flake on a loaded dev server:** after the review refactor, "the five pieces start ... about 300ms apart" failed once on desktop in the first whole-file run (dev server, both projects in parallel; the failing number was not captured), then passed 3 of 3 alone and 3 of 3 whole-file; the 19 hero tests also passed on a `CI=1` production build. If it recurs, capture the gap value before touching the 200 to 400ms window; CI runs the production build with one retry (`playwright.config.ts`).
- **Playfair Display digits are not tabular:** `tabular-nums` changes nothing (widths 26.6 to 43.2px at 72px), so never reserve number width in `ch`; reserve the real width with an invisible copy (`CountUp.tsx`).
- **jsdom has no `IntersectionObserver`:** Motion's `useInView` throws in unit tests. `onViewportEnter` works for `CountUp` (it is only called in the browser), but `whileInView` on a mounted `Reveal` threw `IntersectionObserver is not defined` on 2026-11-15: stub a no-op class with `vi.stubGlobal` (see `components/motion/Reveal.test.tsx`).
- **Read the vitest summary line, not the tail of the output:** `npm test | tail` can end on a timing blurb and hide `Tests 18 failed`; use `npx vitest run | grep -E "Test Files|Tests "`.
- **Hover tests only on desktop:** Tailwind wraps `hover:` in `@media (hover: hover)`, so the `mobile` (Pixel 7) project has no hover lift; skip it with `test.skip(testInfo.project.name === "mobile", ...)`.
- **Measuring JS size:** Next 16's build prints no "First Load JS" table. Serve the build with `npx next start -p 3100` and sum the gzip size of each page's `<script src>` files (script used 2026-11-08 lived in the session scratchpad; it is 30 lines). Stop that server before rebuilding.
- **Python file edits on Windows:** open files with `encoding="utf-8"` and `newline=""`. The default encoding wrote lone `0xB7` bytes into `docs/decisions.md` on 2026-11-06 (fixed in `4c36116`). Check with `python -I -c "open(p,'rb').read().decode('utf-8')"`. Keep multi-line Python in a scratch file: Git Bash heredocs with quotes broke once.
- **Full e2e needs port 3000 free:** `CI=1 npx playwright test` refuses to start if a dev server holds the port (stop the node process running `next ... start-server.js`; the permission classifier blocks that until Ashley says yes). Without `CI=1`, Playwright starts or reuses `npm run dev`.
- **View-transition tests:** the browser sometimes reports zero-length animations on the transition groups; assert on animations with a duration above 0 (`e2e/page-transition.spec.ts`).
- **The Claude in Chrome tool's `resize_window` does not change the viewport** (`innerWidth` stayed 1920). For 390 px screenshots use the Playwright MCP (`browser_resize`, `browser_navigate`, `browser_click`, `browser_take_screenshot` with a `.playwright-mcp/` filename). Playwright e2e specs set their own viewport with `page.setViewportSize`.
- **`impeccable live-generate`:** after the helper injects its script into `app/layout.tsx` you must reload the tab, then rerun the command, or it reports `no_browser_connected`. `live-server stop` restores `app/layout.tsx`. A header variant needs `position: sticky` and the preview wrapper (`display: contents`) can break it; the hero already pulls under the header with `-mt-(--header-height)`, so keep any sticky header in the flow.
- **Testing a swipe in Playwright:** `Input.synthesizeScrollGesture` (CDP) did nothing under Pixel 7 emulation; real touch events work: `cdp = await page.context().newCDPSession(page)`, then `Input.dispatchTouchEvent` `touchStart`, ten `touchMove`s, `touchEnd`. Desktop Chrome has no touch unless the spec calls `test.use({ hasTouch: true })` (done in `e2e/model-shots.spec.ts`). Wait about 800 ms after `scrollIntoViewIfNeeded()` before measuring a position (smooth scrolling), or the touch lands in the wrong place.
- **Tests on `getComputedStyle` colours:** they can be `lab()`/`oklch()`; convert with `toRgb` in `e2e/color.ts` before comparing to an rgb literal.
- **`impeccable generate` on sibling sections:** the four homepage sections have no shared parent, so a temporary wrapper `div` was added in `app/page.tsx` for the preview and removed afterwards with `git checkout -- app/page.tsx`. The accepted preview was rebuilt test-first, not carbonized. `live-generate` piped through `head` shows no output until it exits: write it to a file instead. Never commit while the helper is live (`live-server stop` restores `app/layout.tsx`).
- **Staging part of a file** (no interactive `git add -p` here): hash the wanted version into a blob and `git update-index --cacheinfo 100644,<blob>,<path>`; that is how the `id="model-shots"` line went into the hero commit apart from the carousel rewrite.
- **Smooth scrolling hides a failed scroll test:** `html` uses `scroll-smooth`, so `scrollY` reads 0 right after a wheel event. Wait (about 600 ms) before asserting a scroll was blocked, and confirm the test goes red first.
- **Local e2e reuses a running dev server** when not run with `CI=1`; `npm run dev` may still be running from this session (started in the background, port 3000).
- Windows. Bash and PowerShell both work. Python writes CRLF unless you open files with `newline=""`.
- Agent worktrees under `.claude/worktrees/` get picked up by Vitest and ESLint: remove them when done. A fresh checkout or worktree needs `npm ci`.
- e2e: `CI=1 npx playwright test` (builds and serves; uses installed Chrome, D-15). Specs must import `test`/`expect` from `e2e/fixtures.ts` (ESLint enforces it): its auto fixture aborts the contact server action so no e2e test can email Mason. On 2026-11-06 the dev server was stopped before running it (a precaution; not tested whether that is needed).
- `.env.local` holds the **real** `RESEND_API_KEY`, and local e2e reuses a running `npm run dev`. Never submit a valid form outside the fixture or against the real action. Never print the key.
- Vitest aliases `server-only` to its no-op (`vitest.config.mts`); Next's build still enforces it.
- Git Bash rewrites `/c` to `C:/` in arguments (e.g. `cmd /c`); run those from PowerShell.
- Playwright MCP (`@playwright/mcp@0.0.83`, Chrome) blocks `file:` URLs and only saves files inside the repo in `.playwright-mcp/`, now **gitignored** (commit `9870d92` on `feat/redesign`). A first screenshot can predate Tailwind's rebuild on the dev server: wait, then reshoot.
- **Scroll reveal and screenshots:** the `Reveal` blocks sit hidden until scrolled into view, so a full-page screenshot without scrolling shows blank sections. Capture with `page.emulateMedia({ reducedMotion: "reduce" })` (that is how the "after" images were taken), or scroll each section into view with animation frames running (set `document.documentElement.style.scrollBehavior = 'auto'` first, then wait about 1.8s per section). Lazy images also stay unloaded in unscrolled captures.
- `next dev` writes an untracked `AGENTS.md` in the repo root ("Generated AGENTS.md for AI agents"). Don't commit it. Specs live in `docs/specs/` (created 2026-11-06; the repo had none); this file is the pointer to them, because that `AGENTS.md` is generated.
- Public repo: only Mason's resume PDF and reel thumbnails show his phone number (D-35). Never put it in code, tests, docs, issues or commits. Never commit `.env.local`.
- Tickets use labels `ready-for-agent` / `needs-human`; PRs close issues with `Closes #N`.
